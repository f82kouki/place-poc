# 検証用URL一覧（PoC作戦書 §4）
#
# 書式: 分類<TAB>URL<TAB>期待する店名     ← 区切りは必ずタブ
# URL欄が空の行はスキップされる。埋めた行だけが実行される。
#
# ⚠️ 素直な店だけで試すと「うまくいった」という誤った結論が出る（§4）。
# ⚠️ vimmy の実データや取引先の店は使わない。公開されている有名店・チェーンで十分。
# ⚠️ G1 / G2 は A1 と「同じ店」の別系統URL。別の店を入れると系統差か店差か分からなくなる。
#
# 分類  選び方                                     何を見るか
# A1    素直な単独店（路面店・独自の店名）          ベースライン
# A2    素直な単独店・飲食以外（美容室/整体など）    飲食以外でも営業時間が返るか
# B1    同名チェーン（同一エリアに複数）            ① 先頭1件が貼ったURLの店か
# B2    同名チェーン（徒歩数分に同名店）            locationBias が効いているか
# C1    雑居ビル内（同座標に複数テナント）          ① 別テナントを掴まないか
# C2    地下・空中階の店（5F など）                座標が建物単位になり精度が落ちないか
# D1    一般名詞すぎる店名（「和食 山田」「BAR」）   ① 検索が発散しないか
# E1    閉店・移転した店                           ⑥ businessStatus で気づけるか
# F1    大型施設内テナント（モール・駅ビル）        住所が施設名だけになる等の崩れ
# G1    A1と同じ店の ?api=1&query_place_id= 形式    ③ 系統差の比較
# G2    A1と同じ店の ?cid= 形式                    ③ 何も取れないことの確認
# H1    店舗ではないURL（駅・住所ピン・/maps/@）     正しく失敗するか（本編 §5-2）
